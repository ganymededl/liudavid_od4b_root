Copilot Chat for your users

Quickstart for admins to build and host a self-contained Copilot Chat prompt site for adoption. This condenses the runbook into prerequisites plus step-by-step execution that works for GitHub Pages, intranet, or SharePoint Online hosting.

Quickstart (HTML) - admin path

Prerequisites

  • Copilot Cowork access and a new project folder.
  • Two short MP4 background clips and five short MP3 audio cues.
  • Four target back-office roles and three repetitive daily tasks per role.
  • Reference layout from the NYPD or MTA Copilot Chat prompt experience.

Build steps

  1. Create one flat folder and keep media at root with index.html (no nested media path).
  2. Generate a single self-contained HTML page with inline CSS/JS and local media references.
  3. Add role cards, prompt cards, copy buttons, and clear "what it does" + "good output" notes.
  4. Include light/EDU mode toggle, background video cross-fade, and user-triggered classroom audio controls.
  5. Test locally: cross-fade timing, copy-to-clipboard, mode persistence, and no external network dependencies.
  6. Publish path:
    • SharePoint/intranet: upload folder, open in browser context where autoplay controls are allowed.
    • GitHub Pages or Azure Static Web Apps: publish static assets for easy org sharing.
    • If media is large: move media files to Azure Blob and replace with SAS URLs.
  7. Operationalize: keep version notes in footer and set reminders before SAS expiry if used.

Tips and tricks (from runbook)

  • Keep video files under ~12 MB each for faster first-load over school networks.
  • Use lowercase hyphenated filenames (no spaces) to avoid case/path breaks after publishing.
  • Audio must be user-triggered ("Class is in session"); do not force autoplay audio on load.
  • If copy-to-clipboard fails under file://, use a fallback copy method in the page script.
  • Edit HTML in VS Code/Cowork/Notepad only; smart quotes from Word can break JavaScript.

Troubleshooting

  • Video not playing: path/filename mismatch is the first thing to check.
  • Media returns 403 after Blob hosting: regenerate SAS URL and check for trailing spaces in pasted links.
  • SharePoint preview behavior differs: autoplay/video controls are often restricted in Office preview; test in a regular browser too.
  • Cowork preview quality can look compressed; validate playback in a direct browser tab before final sign-off.

https://freesound.org/search/?q=classroom
