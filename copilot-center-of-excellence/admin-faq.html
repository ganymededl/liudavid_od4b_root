Question 1 Which release should I deploy, where is the approved ZIP, and what is its hash? Release & integrity

Use the approved v3.8.21 installation ZIP provided with your deployment materials.

Before extracting it, verify this SHA-256 hash:

B31F641642BD2199C36C3F840F5A4878CEE8332E89B5C3AB4EC09FF72B264D6F

Keep the matching release receipt with your deployment records. See Question 7 for the PowerShell command and Question 8 for checking a copied package.

A GitHub ZIP is valid installation media when the release explicitly lists Copilot-CoE-Implementation-Kit.zip as a prebuilt asset and its published hash matches. Do not substitute GitHub's automatic Source code (zip), Source code (tar.gz), or repository Download ZIP. Release 3.8.21 currently has no binary asset, so its approved installation ZIP is distributed separately.
Question 2 What should our security-incident reporting page contain? Incident reporting

Configure an approved HTTPS reporting page in Links.DataSafetyIncident. It may direct users to a monitored mailbox or reporting form. Use your organization's existing security-reporting process; use a form or ticketing portal when the process requires tracking, assignment, and escalation.

The page should name the responsible team, explain urgent and after-hours reporting, and say when users should expect confirmation. The kit displays a link to this process; it does not provide incident management.

See Question 33 for report contents and Question 37 for testing the process.

Question 3 What roles and permissions are required to register, install, validate, and maintain the CoE? Roles & permissions

The minimum-role configuration has not yet been fully validated. Testing covered a Global Administrator installing as the configured owner and installing for a different owner.

Verified requirements:

  • An approved consent approver must register the app and grant tenant-wide admin consent.
  • The configured shared-channel owner must be an existing in-tenant Member account.
  • The app must have delegated Graph Group.ReadWrite.All, ChannelMember.ReadWrite.All, User.Read, User.Read.All, and SharePoint AllSites.FullControl.
  • The person running each script must be permitted by your tenant to perform its Teams, Microsoft 365 group, user, and SharePoint operations.

Not yet tested: a non-Global-Administrator installing for a different owner. This may fail when the script writes governance files.

Naming-policy requirement: Global Administrator and User Administrator are exempt from a Microsoft Entra group naming policy that changes aliases. That exemption alone does not grant every permission needed for installation.

See Question 88 to register the app and Question 87 for what happens to it after installation.

Question 4 How do we know the deployment is production-ready? Production acceptance

A successful installation does not mean the site is ready for users.

Before launch:

  1. Run Test-CoEInstall.ps1 from the same kit release, using the same -ContentMode.
  2. Fix every FAIL.
  3. Complete and record the manual checks and evidence listed in every WARN.
  4. Test the site with a regular, non-owner account.
  5. Check all three Teams welcome posts, their author, and their links.
  6. Confirm that support and incident-reporting links work and are monitored by the responsible teams.
  7. Obtain your organization's required security, privacy, records, accessibility, licensing, and operational approvals.

See Question 41 for the full installation command, Question 50 for the checker command, and Question 56 for retained evidence. Question 85 lists everything installation creates, and Question 86 covers tenant-level settings.

ALL CHECKS PASSED confirms the automated checks passed. It does not replace the manual checks.
Question 5 What will an update overwrite? Safe customization

What gets replaced depends on the content type:

  • Generated guide and section pages: a Guides or All update rebuilds kit-managed page content from the organization folder. Direct SharePoint body edits are replaced.
  • Home and the four prebuilt pages: ordinary updates preserve certain customized page elements. They can still change navigation, headers, comments, calendar controls, and other managed settings. -RepairCapturedPages replaces the managed elements listed in Question 61.
  • Governance Word drafts: a difference stops the update unless -ReplaceFiles authorizes replacement.
  • Organization-provided reference files: kept unless -ReplaceOrgAssets is used.
  • Live lists: existing prompt, agent, learning, calendar, champion, and story rows are kept. The kit can still change fields, views, approval settings, and permissions on those lists.

Make lasting generated-page changes in the organization folder, not only in SharePoint. See Question 58 and Question 61 for details.

Question 6 What should I do after a failed installation? Failure & rebuild

Do not immediately run a new installation or delete the resources.

  1. Save the installation transcript under <OrgPath>\RevisionAudit.
  2. Check whether the intended Team and SharePoint site were created.
  3. Identify and fix the cause of the failure.
  4. If the correct resources exist, resume that installation with -ResumeExisting.

See Question 76 before resuming.

If you decide to discard this deployment and start again:

Back up any content you need before continuing. The commands below permanently delete the Team and related SharePoint sites.

First, preview the removal:

$orgPath = 'C:\path\to\organization-folder'
.\04_Remove-CopilotCoE.ps1 -OrgPath $orgPath -Purge -WhatIf

Only if you intend to permanently delete the resources shown in the preview, run:

$orgPath = 'C:\path\to\organization-folder'
.\04_Remove-CopilotCoE.ps1 -OrgPath $orgPath -Purge

The script will ask you to type the alias, and then type each exact site URL shown in the plan, before anything is purged (Question 81). Wait for AliasReusable : True before installing again with the same alias.

Do not run these removal commands if you are continuing with the existing deployment. Resuming an interrupted installation tests recovery; it does not demonstrate that a new installation will succeed.
Question 7 How do I verify the ZIP before extracting it? Release & integrity

Run this before extracting the package:

$zip = 'full path to Copilot-CoE-Implementation-Kit.zip'
$expected = 'B31F641642BD2199C36C3F840F5A4878CEE8332E89B5C3AB4EC09FF72B264D6F'
if ((Get-FileHash -LiteralPath $zip -Algorithm SHA256).Hash -ne $expected) {
    throw 'The ZIP does not match the approved release.'
}

Stop if the hash differs. Verify it again after copying the ZIP to another location.

Question 8 How do I check whether my copy is the correct release? Release & integrity

Compare the ZIP's SHA-256 hash with the expected hash in the release receipt. Do not rely only on the filename, modified date, or folder name.

If the hash does not match, stop and obtain the approved package from the release owner.

Question 9 Why can VERSION.txt differ from CoE-Revision-Content.json? Release & integrity

VERSION.txt identifies the packaged kit release, such as 3.8.21. The version inside CoE-Revision-Content.json in the base or Government content pack identifies a content revision. They serve different purposes and can legitimately differ. Do not relabel content revisions just to match the package version.

Question 10 How do I determine which kit and content revision built an existing deployment? Release & integrity

Use the retained ZIP and hash and its root VERSION.txt for the kit release. Use CoE-Revision-Report.json for the last completed deployment's site and content revision. The report is not a reliable substitute for the original package record, especially after a stopped update.

If the original ZIP, hash, and transcript were not retained, the exact kit release may not be provable from the live site alone.

Question 11 Can I reuse an older extracted kit folder? Release & integrity

Use a fresh extraction of the verified ZIP for each release and each validation of a new installation. A used extraction can contain generated templates, audit data, organization-specific names, or files left by an interrupted run. Keep old extractions privately for troubleshooting, but do not use them as new installation media.

Question 12 What release and deployment evidence should we retain? Release & integrity
  • Approved release ZIP, SHA-256 hash, version, and release receipt.
  • Organization settings, Content, and Assets as deployed.
  • Transcripts from the installation, content-update, and removal scripts, plus checker outputs.
  • CoE-Revision-Report.json, removal manifest, advisory decisions, and purge receipt where applicable.
  • Copies saved before updates, screenshots, recorded confirmation that manual checks were completed, and support-route ownership evidence.

Store deployment evidence privately. Do not include it in the organization-neutral installation package.

Question 13 Which Microsoft 365 environments are supported? Environment & prerequisites

The scripts are designed for commercial and GCC Moderate tenants. This release has not been validated in a GCC Moderate tenant. GCC High and DoD are not supported.

Question 14 Does the Government content pack configure GCC Moderate? Environment & prerequisites

No. LearningEnvironment: Government and the Government content pack select wording, prompts, links, and learning content. They do not change cloud endpoints, tenant policies, authentication authority, licensing, or compliance boundary.

Question 15 Which PowerShell and PnP.PowerShell versions are required? Environment & prerequisites

Use exactly PnP.PowerShell 3.2.0: the scripts import it with -RequiredVersion 3.2.0, so a newer installed version is not used automatically. Run Install-Module PnP.PowerShell -RequiredVersion 3.2.0 -Scope CurrentUser first if you don't have that version.

The scripts require PowerShell 7.4 or later (each starts with #Requires -Version 7.4) and will refuse to start in Windows PowerShell 5.1.

Question 16 Why is each delegated permission requested? Roles & permissions
  • Group.ReadWrite.All: creates and manages the Microsoft 365 group and Team. Microsoft Graph also still accepts this permission for posting channel messages, as a backward-compatible permission alongside ChannelMessage.Send. The kit uses this to send the three welcome posts and does not request ChannelMessage.Send separately.
  • ChannelMember.ReadWrite.All: creates and validates governance shared-channel membership.
  • User.Read: signed-in user identity.
  • User.Read.All: verifies whether governance users are Member or Guest accounts.
  • AllSites.FullControl: provisions and configures SharePoint sites, pages, lists, files, navigation, permissions, and sharing.

The kit does not request ChannelMessage.Read.All either. That permission would let the checker read posts directly; instead the kit relies on the manual Teams inspection in Question 54.

Question 17 How do I confirm all permissions are granted? Roles & permissions

In Entra admin center, open App registrations, select Copilot CoE Provisioning (PnP), and open API permissions. All five requested permissions must show Granted before running 02_Install-CopilotCoE.ps1. If consent changed, use a fresh interactive sign-in for the next operation.

Question 18 Which account should run installation, and whose name appears on welcome posts? Roles & permissions

The signed-in operator is shown as the author of Teams welcome posts. Use an approved CoE owner or dedicated provisioning administrator when attribution matters. The recommended tested configuration uses the operator as the configured SharedChannelOwnerUPN; a Global Administrator installing for another owner was also tested.

Question 19 What if the owner differs from the operator? Roles & permissions

The installation script asks whether to continue before it creates resources. The governance shared channels contain the configured owner and do not automatically add the person running the script. A Global Administrator installing for a different owner was tested successfully. A non-Global-Administrator installing for a different owner has not been tested and may fail when writing governance files.

Question 20 What if authentication opens the wrong tenant or cached account? Environment & prerequisites

Stop and verify Tenant, AdminFQDN, SiteFQDN, and PnPClientID. Add -AuthenticationMode Interactive -ForceAuthentication to the installation, content-update, or removal command when a fresh browser sign-in is needed. Confirm the account and tenant shown by the sign-in flow before continuing.

Question 21 When should I use ForceAuthentication, and what cannot be combined? Environment & prerequisites

Use -ForceAuthentication after consent changes, when switching tenants or accounts, or when a stale cached identity is offered. It requires -AuthenticationMode Interactive; do not combine it with DeviceLogin. Script 01 uses its separate -Interactive switch.

Question 22 What must be customized in Deployment-Settings.json? Organization settings

Edit <OrgPath>\Deployment-Settings.json, the copy created from Org-Template or ContentPacks\Government-StateLocal. Do not edit the generic files under the extracted kit.

Before installation, review these settings:

  • Tenant and app: Tenant, AdminFQDN, SiteFQDN, and PnPClientID. Leave PnPClientID blank before the first script-01 registration in a new tenant; never copy a client ID across tenants.
  • Deployment identity: MailNickname, DisplayName, and SharedChannelOwnerUPN. MailNickname controls the Team alias and SharePoint site path; changing a checker $siteUrl does not change the installation target.
  • Organization details: OrgName, OrgNoun, ShortName, OrganizationEmailDomains, SupportEmail, and TimeZone.
  • Access: TeamVisibility, CoESiteSharingCapability, GovernanceAdditionalAllowedMembers, and CatalogReviewerUPNs.
  • Links: the entries under Links, plus GovernanceLinks and TrainingLinks.
  • Content and navigation: LearningEnvironment, EnvironmentLabel, SampleNotice, PromptLibrary, ChampionDepartments, Agents, NavigationOrder, NavigationPinFirst, EnableDeveloperTrack, GuidesIntro, StoryAudiences, and ScenarioLibraryUrl.

Replace all placeholders and check every value that users will see. The main installation guide's step 04 now provides a field-by-field worksheet with examples and value sources.

If you supply Content\Training-Calendar.csv: use the current StartOffsetDays schema, not fixed StartDate/EndDate columns. The scripts check this before connecting to the tenant.
Question 23 Which template should higher education, government, or commercial organizations use? Organization settings

Use Org-Template as the neutral default starting point for higher education. State and local government uses ContentPacks\Government-StateLocal. Commercial organizations can start from Org-Template and replace education-specific content with reviewed organization overrides. There is no separate Commercial content mode.

Question 24 Where should the organization folder live? Organization settings

Keep it outside the extracted kit, for example C:\CoE-Orgs\Contoso or an approved customer folder. This keeps settings, Content, Assets, transcripts, and identity records across kit upgrades without modifying shared installation media.

Question 25 Can I reuse a completed organization folder or copy one to a new deployment? Organization settings

Reuse the same folder for updates to the same deployment. For a new site, create a fresh folder and copy only reviewed settings, Content, and approved Assets. Change the alias and any site-specific links. Do not copy files that record the previous deployment and installation status.

Question 26 Which identity files must never be copied to another site? Organization settings

Do not copy CoE-Revision-Report.json, CoE-Removal-Manifest.json, CoE-Purge-Receipt.json, CoE-Advisory-Decisions.json, installation-wrapper state, or RevisionAudit. These files identify the previous deployment and must not be used for a different site.

Question 27 How should I choose MailNickname, and what if it is active or recycled? Organization settings

Choose a tenant-unique alias using letters, numbers, hyphen, or underscore, up to 64 characters. 02_Install-CopilotCoE.ps1 checks active groups, sites, and recycle bins before creating anything. If a naming policy changed the alias during provisioning, inspect Entra before trying again; another new installation could create a duplicate Team.

Question 28 Which names, domains, mailbox, timezone, and URLs require review? Organization settings

Verify OrgName, DisplayName, ShortName, OrgNoun, allowed email domains, monitored SupportEmail, Windows timezone ID, and every HTTPS destination. Test the links as a normal intended reader; syntax validation does not prove access, delivery, ownership, or monitoring.

Question 29 Why must the Team remain private, and what should I do with sharing warnings? Organization settings

The kit requires a Private Team and defaults the parent and governance sites to external sharing Disabled. Do not loosen tenant, site, Team, label, or cross-tenant policy just to finish installation. Investigate the actual membership or sharing issue and rerun after it is corrected. Question 86 covers what the kit does and does not change at the tenant level.

Question 30 Can the incident route be a monitored email address, or should it be a form? Incident reporting

The kit accepts an HTTPS page, not a mailto address. That page can present an approved monitored mailbox, but a form or service-management portal is usually preferable when the organization needs required fields, assignment, audit history, escalation, and status tracking. The security or privacy owner must approve the choice.

Question 31 Can we use our existing reporting page? Incident reporting

Yes. A working organization-approved security or privacy reporting form or instructions page is preferred over creating a Copilot-only system. Use a dedicated Copilot page only if the existing process cannot give users clear, accessible instructions and correct routing.

Question 32 Who should own and monitor the incident route? Incident reporting

The organization must assign this explicitly. Typically Security Operations or an incident-response team handles urgent reports, with Privacy, Legal, Records, and the service desk participating under established procedures. The CoE can explain the route but should not become the official place where incidents are recorded and tracked unless that responsibility is formally assigned.

Question 33 What information should users provide in an incident report? Incident reporting

Recommended minimum: when it occurred, affected service, brief description, suspected data classification, who may have received access, immediate containment actions, and reporter contact details. Reference the record or conversation rather than copying sensitive content into an unapproved channel.

Question 34 What should users avoid including? Incident reporting

Do not paste passwords, secrets, regulated identifiers, case details, complete prompts and responses, screenshots, or files containing sensitive information unless the approved reporting process explicitly protects and requests them. Follow legal-hold and evidence-preservation instructions.

Question 35 Should the page explain urgent escalation, after-hours reporting, and response times? Incident reporting

Yes, if those commitments are approved. State what qualifies as urgent, the after-hours route, when users should expect confirmation that their report was received, and what they should do while waiting. Do not invent a response time in the CoE page; link to or quote the organization's real process.

Question 36 How are incidents different from support, technology requests, and policy questions? Incident reporting
  • Incident: suspected exposure, misuse, security or privacy harm, or urgent containment.
  • ServiceDesk: break/fix, access, or ordinary help.
  • TechnologyRequest: new capability, licensing, integration, or change request.
  • AIGuidelines: policy interpretation and approved-use guidance.

Configure distinct routes even if one portal sends requests to different teams.

Question 37 How do we verify the route works for non-owners? Incident reporting

Sign in as an ordinary intended reader, open the CoE link, and submit a harmless test through the approved process. Confirm that the report is received by the responsible team and that no elevated permission is required. Record the test date and the team's confirmation.

Question 38 What happens if the incident URL is blank, malformed, inaccessible, or unmonitored? Incident reporting

A malformed or non-HTTPS URL stops configuration. A blank route triggers STOP / PROCEED unless explicitly allowed for a reviewed demo; pages show a not-configured warning rather than a working service. An inaccessible or unmonitored route can pass a syntax or link check, so test the reporting process yourself before launch.

Question 39 Does the kit provide incident management? Incident reporting

No. It displays a link to the organization's configured route. It does not create a monitored mailbox, ticket queue, responder schedule, investigation process, notification workflow, or response-time commitment.

Question 40 What is the difference between Customer and Demo mode? Install behavior

Customer suppresses demo notices and seeded sample calendar and catalog data and checks for demo text or sample content appearing on a customer site. Demo requires a visible sample notice and allows sample rows. The selected mode is not saved on the site, so pass the same mode to the installation script, content-update script, and checker.

Question 41 Why is SeedDemoContent required for a production Customer installation? Install behavior

The name is historical and misleading. -SeedDemoContent (alias -PublishContent) means publish the CoE pages, catalogs, calendar structure, prompts, and governance content. -ContentMode Customer is what keeps demo content out.

The full command for a production Customer installation:

$orgPath = 'C:\path\to\organization-folder'
.\02_Install-CopilotCoE.ps1 -OrgPath $orgPath -ContentMode Customer -SeedDemoContent

The script prints the new site URL at the end. Run the checker against that URL and the same mode:

.\Test-CoEInstall.ps1 -OrgPath $orgPath -SiteUrl '<site URL the install script printed>' -ContentMode Customer

Question 85 lists everything this creates in your tenant.

Question 42 What is created if I omit SeedDemoContent? Install behavior

02_Install-CopilotCoE.ps1 creates the Team and SharePoint site but skips the CoE pages, catalogs, calendar content, prompts, and governance documents. The result is not a complete deployment.

Question 43 Which sample content is excluded in Customer mode? Install behavior

Customer mode suppresses sample and demo notices and sample list and calendar rows. Organization Asset filenames containing DEMO or SAMPLE as whole words are filtered from hosting offers. Prompt CSVs are not covered by that filename filter; review them separately. Existing rows follow the documented Customer or Demo rules and are not silently rewritten.

Question 44 When is AcceptOrgAssets safe? Install behavior

Only after every eligible file in <OrgPath>\Assets has been reviewed for audience, classification, licensing, freshness, and destination. The switch answers Yes to every hosting prompt; it is not a review mechanism.

Question 45 What does STOP / PROCEED mean, and where is it recorded? Install behavior

STOP / PROCEED asks you to decide whether to continue after a specific warning. It does not override an error that blocks installation.

Your decision is saved in CoE-Advisory-Decisions.json for the specific tenant, site host, alias, warning, and conditions shown. If those conditions change, the script asks again.

A saved STOP continues to block the run until you deliberately change the configuration or saved decision. Choosing PROCEED is not production approval.

Question 46 Does PROCEED mean production approved? Install behavior

No. It means the operator accepted only that warning for this deployment and the conditions shown. It does not prove monitoring, accessibility, security approval, correct rendering, or customer acceptance.

Question 47 How long does installation take? Install behavior

Plan for roughly 25–35 minutes in a typical tenant. Adding 230 prompt rows often accounts for 5–10 minutes. Tenant propagation, throttling, catalog setup, and shared-channel provisioning can make the installation take longer.

Question 48 How do I validate an organization-provided installation wrapper? Install behavior

An organization-provided installation wrapper is an optional script outside the kit that supplies organization-specific arguments or tracks its own state. Confirm that it calls 02_Install-CopilotCoE.ps1 with the intended -OrgPath, -ContentMode, -SeedDemoContent, authentication options, and only reviewed asset switches. Treat the wrapper's state and reset logic as separate from the numbered scripts.

Question 49 Does installation run the checker automatically? Production acceptance

No. Run Test-CoEInstall.ps1 separately after every install and every update, using the checker from the same release extraction.

Question 50 Which checker version and ContentMode should I use? Production acceptance

Use the checker shipped in the deployed release and pass the same -ContentMode Customer or Demo. Omitting the mode skips checks that apply specifically to Customer or Demo mode.

Run it against the site URL the install script printed:

$orgPath = 'C:\path\to\organization-folder'
.\Test-CoEInstall.ps1 -OrgPath $orgPath -SiteUrl '<site URL>' -ContentMode Customer
Question 51 What do PASS, WARN, MANUAL REVIEW REQUIRED, and FAIL mean? Production acceptance
  • PASS: that check succeeded.
  • WARN: automation cannot confirm a required condition; complete and record the manual check described in the warning.
  • MANUAL REVIEW REQUIRED: the automated checks may have passed, but one or more WARN items still need review.
  • FAIL: the checker found a problem or could not complete a required check. Do not approve the deployment.
Question 52 Why can automation pass while manual review is still required? Production acceptance

Automation cannot prove browser layout, human-readable wording, real endpoint ownership and monitoring, how posts look in Teams and which account is shown as the author, non-owner access, or organizational approval. It also deliberately lacks tenant-wide message-read permission.

Question 53 What should be tested with a non-owner account? Production acceptance

Open parent-site pages, navigation, lists, hosted assets, support and incident links, learning content, and the intended Teams tabs and posts as a normal reader. Confirm governance sites remain inaccessible unless the user is explicitly approved. Validate any lab guest separately.

Question 54 How do I verify the Teams welcome posts? Production acceptance

Inspect General, Ask Us Anything, and Share Your Prompt. Confirm exactly one prepared post per channel, correct operator attribution, correct links and content, and no Customer-mode demo notice. On resume, use -PublishWelcomeToChannels only for channels visually confirmed missing.

Question 55 Should I grant ChannelMessage.Read.All to remove a warning? Production acceptance

No. The kit intentionally does not request tenant-wide message-read permission just for checker convenience. Perform and record the manual Teams inspection instead.

Question 56 What evidence should we retain before launch? Production acceptance
  • Automated checks: the checker output from the final run.
  • Manual checks: screenshots taken at normal laptop width, the three-post Teams inspection (Question 54), and the non-owner access test (Question 53).
  • Approvals: support and incident-route owner confirmations, the security and sharing review, asset approvals, and the catalog reviewer and approval review.
  • Records: run transcripts, plus the final acceptance decision tied to the release hash and site URL.

Question 12 covers the full deployment record.

Question 57 What belongs in the organization folder versus SharePoint? Safe customization

Settings-driven wording, generated page source, starter prompt CSVs, governance draft sources, and hosted Assets belong in the organization folder. After the initial list items are added, maintain live agents, learning paths, champions, calendar entries, success stories, and user prompts in SharePoint unless that feature's instructions say otherwise.

Question 58 Which direct SharePoint edits are overwritten? Safe customization

Direct edits to kit-managed generated guide and section page bodies are replaced by the next Guides or All publication. Managed elements on Home and the four prebuilt pages are replaced only by -RepairCapturedPages. Navigation, header settings, and page comments may also be maintained by updates.

Question 59 What do Scope Guides, Governance, and All change? Safe customization
  • Guides: guide, section, FAQ, and feedback pages; settings-driven links; catalogs; and prompt sources.
  • Governance: the restricted governance shared channels, their SharePoint sites, and managed Word drafts.
  • All: both, plus resources, champions, training calendar, and Top 10 handling.

Guides and Governance require a completed deployment report; All can run without it. Always use the documentation from the deployed release for the exact scope.

Question 60 Why does editing settings or a source file not immediately change the site? Safe customization

Saving a local settings or source file does not update SharePoint. Run 03_Update-CoEContent.ps1 with the appropriate scope, then run the checker. Changes to live list items made directly in SharePoint do not require the content-update script.

Question 61 What does RepairCapturedPages reset? Safe customization

It deliberately rebuilds managed Home elements (title, welcome message and notice, tool links, Explore tiles, champion and calendar areas) and managed title, breadcrumb, and notice elements on the four prebuilt pages: Adoption Best Practices, CoE roles and contacts, Technical Readiness, and Microsoft Mechanics. The Microsoft Mechanics body is also regenerated. Preserve approved direct customizations before using it.

Question 62 What is the difference between ReplaceFiles and ReplaceOrgAssets? Safe customization

-ReplaceFiles authorizes replacing or removing differing managed governance and kit sample files touched by the update. -ReplaceOrgAssets authorizes replacing an existing hosted organization Asset. Neither is a generic force switch; review the exact files first.

Question 63 What if reviewers edited a governance Word document? Safe customization

Copy the approved changes from the published Word document into the matching source file. Without -ReplaceFiles, a Governance or All run stops rather than overwrite a differing managed document. With it, the generated document is rebuilt; custom formatting, comments, and changes not copied to the source file are not carried forward.

Question 64 Can an update stop after publishing some changes? Safe customization

Yes. All processes do guide, section, and catalog work before governance comparison. A differing governance draft can stop the run after earlier changes are live; there is no rollback. The deployment report is written only at successful completion, so an existing report may describe the prior run.

Question 65 Which tokens and placeholders must customized Markdown preserve? Safe customization

Some Markdown files contain placeholders that the kit replaces with organization settings.

  • {{OrgName}}, {{OrgNoun}}, and {{OrgShort}} insert organization names.
  • {{SupportEmail}} inserts the configured support address.
  • {{Link:Key|text}} inserts a configured link.
  • {{MailTo:...}} creates a link to the support email address.

Keep the placeholders you want the kit to manage. Also keep any fallback message shown when a reporting link is not configured. Do not rename headings used by learning-path links unless you update those links too.

Question 66 Does changing DisplayName or MailNickname rename an existing deployment? Safe customization

No. Changing these settings does not rename an existing Team or SharePoint site. Use your approved Teams or SharePoint administration process for the type of rename you need. Do not change MailNickname just to make the content-update script target another alias.

If the administration tools do not support the required alias or URL change, plan a reviewed migration to a new site separately.

Question 67 What should I preserve before an update? Safe customization

Keep the organization folder, live document or version-history backup, current deployment report, run transcripts, copies saved before the update, screenshots and manual-check evidence, and the exact release ZIP and hash.

Content updates also save a before-copy of every replaced managed page in the kit extraction's own RevisionAudit folder — separate from the run transcripts saved under <OrgPath>\RevisionAudit (Question 6). Before replacing an extraction, copy its RevisionAudit folder to your deployment records too.

Question 68 How do I add organization-specific prompts? Prompts & catalogs

Place UTF-8 CSV files under <OrgPath>\Content\OrgPrompts using the Microsoft 365 admin-center format:

Title,Description,Display Prompt,Prompt Text,Products,Department,Task Type,Locale

Maximum 100 prompts per file; titles must be unique per locale and field limits in the OrgPrompts README apply.

Question 69 Will changing a prompt CSV update an existing live prompt? Prompts & catalogs

No. The import adds a prompt only if that Title and Locale combination does not already exist. New rows are added; existing live rows and edits are kept. Update existing prompts in the SharePoint list under the review workflow.

Question 70 How do I remove a base prompt file or all prompt functionality? Prompts & catalogs

An organization CSV with the same name replaces a base file; an empty same-named file omits that base file during seeding. This does not delete rows already in a live list. Set PromptLibrary: Off before initial publication to leave the list out; retire or delete existing rows through reviewed SharePoint administration.

Question 71 Are imported prompts automatically approved? Prompts & catalogs

Prompts seeded from reviewed CSV files are added approved. Prompts people add on the site wait for catalog review. Approval controls publication; it does not validate underlying data sensitivity or licensing.

Question 72 How are catalog reviewers configured, and why might the group be absent? Prompts & catalogs

Add existing in-tenant Member UPNs to CatalogReviewerUPNs. The kit creates CoE Catalog Reviewers and its Contribute + ApproveItems role only when at least one reviewer is configured. Neutral templates use an empty array, so no reviewer group is created by default.

Question 73 Does removing a UPN from CatalogReviewerUPNs remove membership? Prompts & catalogs

No. The kit does not silently downgrade or remove former reviewers. Review the live SharePoint group and remove obsolete members explicitly after confirming intended access.

Question 74 Does approving an Agent Showcase entry grant access to the agent? Prompts & catalogs

No. Approval controls catalog visibility only. It does not share the agent, grant licenses, authorize data sources or actions, or change source-system permissions. Validate actual launch access separately.

Question 75 Where should live agents, learning paths, sessions, champions, and stories be maintained? Prompts & catalogs

Maintain live entries in their SharePoint lists with the configured approval workflow. Starter files add the initial list items and remain the source for future deployments. Most existing rows are kept when the scripts run again.

Question 76 When is ResumeExisting appropriate? Failure & rebuild

Use -ResumeExisting only after an interrupted 02_Install-CopilotCoE.ps1 run created the intended Team or site and you confirmed the tenant, group ID, alias, and exact site URL. Fix the cause, keep the logs, and rerun the same release and settings with -ResumeExisting.

Never use it for a new installation or to validate that a new release can install successfully from the beginning.

Question 77 How do I confirm I am resuming the intended deployment? Failure & rebuild

Before resuming, confirm that the saved deployment records match the resources in your tenant:

  • Tenant
  • Microsoft 365 group ID
  • Team alias
  • Main SharePoint site URL
  • Related shared-channel site URLs
  • Configured owner

Also review the sharing settings and who has access. Do not rely on a similar display name. Stop if the saved records and existing resources do not match.

Question 78 How do I publish a missing welcome post without duplicates? Failure & rebuild

Inspect all three channels visually. On resume, pass -PublishWelcomeToChannels with only the exact names confirmed missing. Ordinary resume skips welcome posts to avoid duplicates.

Question 79 When should I repair or resume instead of rebuild? Failure & rebuild

Resume when the intended Team or site exists and the cause can be corrected. After a completed installation, use 03_Update-CoEContent.ps1 for content or layout repair.

Remove and rebuild only after administrators decide the existing deployment should be discarded and the removal script confirms the alias can be reused.

Question 80 What does the remover delete, and what does Purge make unrecoverable? Failure & rebuild

04_Remove-CopilotCoE.ps1 removes the Microsoft 365 group and Team, main CoE SharePoint site, governance shared-channel sites, conversations, pages, lists, files, navigation, and site-level reviewer permission. A normal removal leaves the resources restorable for the tenant retention period, documented as about 30 days.

-Purge permanently removes the confirmed recycled group and sites and cannot be undone. The Entra provisioning app is retained.

Question 81 Why use Purge -WhatIf instead of deleting only the site manually? Failure & rebuild

The CoE spans a group and Team, the main SharePoint site, and two shared-channel sites. Deleting only the main site leaves related resources and can block reuse of the alias. -WhatIf shows the exact tenant resources that the removal script plans to remove; it does not delete them.

Nothing is removed from the preview alone. Before any removal, the script displays the alias and asks you to type it to confirm. For -Purge, it then displays each exact site URL from the preview and asks you to retype every one, one at a time, before it purges anything.

Question 82 What does AliasReusable: True mean? Failure & rebuild

The removal script's summary shows AliasReusable : True when no matching active or recycled group or site remains for that alias. Wait for this result and keep the purge receipt before starting a new installation with the same alias.

Question 83 Is a reset required before reinstalling? Failure & rebuild

Not for the standard numbered scripts. An organization-provided installation wrapper may keep an InstallAttempted flag and expose -ResetAfterPurge; that reset belongs to the wrapper and only follows verified cleanup. Never fabricate a purge receipt or manually change wrapper state.

Question 84 What must I retain if cleanup is incomplete? Failure & rebuild

Keep the settings, deployment report, removal manifest, group and site IDs, exact URLs, transcripts, -WhatIf and removal output, recycle-bin status, and any partial purge receipt. Do not replace these records or start another new installation until 04_Remove-CopilotCoE.ps1 confirms the result.

Question 85 What does installation create in the tenant? Install behavior

Across scripts 01 and 02:

  • One Entra app registration, Copilot CoE Provisioning (PnP), created once per tenant with the five permissions in Question 16 and tenant-wide admin consent.
  • One private Microsoft 365 group and Team, with its three standard channels (General, Ask Us Anything, Share Your Prompt) and one welcome post in each (Question 54).
  • The main CoE SharePoint site, connected to that Team.
  • Two governance shared channels (Leadership Governance, Program Governance), each with its own SharePoint site and governance Word drafts.
  • SharePoint lists for the prompt library, agent showcase, learning paths, champions, training calendar, and success stories.
  • An optional CoE Catalog Reviewers SharePoint group with Contribute and Approve Items permission, created only if CatalogReviewerUPNs is configured (Question 72).

See Question 80 for what removal deletes and Question 86 for what it does not touch at the tenant level.

Question 86 Does the kit change any tenant-level settings? Organization settings

The kit does not change tenant-wide policy. The one tenant-level object it creates is the Copilot CoE Provisioning (PnP) app registration and its tenant-wide admin consent (Question 16); removal keeps this app rather than reverting it (Question 87). Otherwise, the scripts change settings only on the CoE's own resources: the Team's visibility (Private) and the sharing capability of its own SharePoint sites (CoESiteSharingCapability, Question 29). They do not change the tenant-wide sharing ceiling, Microsoft 365 Groups or Teams creation and guest policies, Conditional Access, retention, or sensitivity-label policies.

The kit also does not apply a sensitivity label or retention policy to the Team or site; apply one through your organization's normal process if required. Tenant-wide policy can still block access even when the CoE's own site sharing is On, so review it separately with your security and compliance team.

Question 87 Can we disable or remove the provisioning app, and how do we delete it when we decommission the CoE? Roles & permissions

Keep the app and its consent in place while you intend to run 02_Install-CopilotCoE.ps1 or 03_Update-CoEContent.ps1 again — both sign in through this app with delegated permissions, so disabling it or revoking consent blocks the next install or update. 04_Remove-CopilotCoE.ps1 also signs in through this app, so keep it in place through removal; the script keeps the app afterward so you can rebuild, whether or not you use -Purge.

Delete it only after 04_Remove-CopilotCoE.ps1 reports AliasReusable : True (Question 82) — removal itself still needs the app. When you're ready: Entra admin center > App registrations > All applications > Copilot CoE Provisioning (PnP) > Delete, then clear PnPClientID in your settings file. The removal script prints these exact steps at the end of every run.

Question 88 How do I register the app with script 01, and can we use an existing app registration? Roles & permissions

Run .\01_Register-CoEProvisioningApp.ps1 -OrgPath $orgPath once per tenant, as an approved consent approver. It defaults to device-code sign-in; many tenants block that flow through Conditional Access, in which case use -Interactive for a pop-up browser sign-in instead (Question 89 covers this trade-off for all four scripts).

It registers a new, single-tenant app named Copilot CoE Provisioning (PnP) and saves its Application (client) ID to PnPClientID in <OrgPath>\Deployment-Settings.json; the kit does not support pointing it at an existing, separately created app registration. An additional organization profile in the same tenant may reuse the client ID of the kit-created, consented app. Never copy that ID to another tenant. An approved consent approver must grant tenant-wide admin consent before Question 17's check shows all five permissions as Granted.

Question 89 What licenses do people need, and do Conditional Access or device-compliance policies affect sign-in? Environment & prerequisites

Viewing the CoE site and Team needs only ordinary Teams and SharePoint access; no Microsoft 365 Copilot license is required just to browse it. Each person's own Copilot license still governs whether they can run Copilot itself, and pages that reference Copilot work prompts note that a license is needed. Whether the configured SharedChannelOwnerUPN or the operator need a specific Teams or SharePoint license has not been tested; Question 3 covers the account type that is verified.

Script 02 defaults to -AuthenticationMode Interactive (a pop-up browser sign-in). Scripts 01, 03, and 04 default to device-code sign-in instead. Many tenants block the device-code flow through Conditional Access; if yours does, pass -AuthenticationMode Interactive (Question 21), or -Interactive for script 01. Conditional Access and device-compliance policies are evaluated against the device where you complete the browser sign-in, which is not necessarily the machine running the script.

Right-click the verified ZIP, open Properties, select Unblock if it is shown, then Extract All; keep the folder structure. Do this for a copied or re-downloaded ZIP too, since each copy can be blocked again by Windows.
