GCC Copilot CoE Install Walkthrough - Eight Steps

INTRO
In this walkthrough, we'll install the Copilot Center of Excellence kit in a GCC Moderate tenant, following the eight-step process used in the MNIT GCC run.

We'll verify the release package, configure the organization settings, check the tenant and signed-in account, and run the installation. Then we'll test the result, complete the manual review, and publish a reviewed update.

STEP 1 - Verify and extract the release package
First, compare the release ZIP's SHA256 hash with the expected value in the release receipt. Continue only if they match.

Extract the package into a new, empty install folder. Then create a separate organization folder outside the kit.

Keep the deployment settings and records there so replacing the kit won't overwrite them.

STEP 2 - Edit the organization settings
Open the organization's copy of Deployment-Settings.json, not the template inside the kit.

Check the tenant details, SharePoint hosts, site alias, visibility, and security settings.

If this tenant needs a new provisioning app, leave PnPClientID blank until the registration script fills it in. For government content, set LearningEnvironment to Government.

STEP 3 - Configure support links and reviewed content
Add the organization's approved support and incident-reporting links, along with its governance links, training resources, and custom content.

Customer mode controls the kit's generated demo notices. It does not approve the content or guarantee that every sample item has been removed.

Before publishing, have the responsible teams review the governance drafts, support routes, and organization-specific wording.

STEP 4 - Check the content before signing in
From the kit folder, run the local content preflight.

This checks the organization's content files, including the calendar format and required fields, before connecting to the tenant.

Fix any reported issues before continuing.

STEP 5 - Install PnP.PowerShell and register the app
Install PnP.PowerShell version 3.2.0.

If the tenant needs a provisioning app, have someone authorized to grant the required permissions run script 01. Confirm that it writes a client ID to PnPClientID in the organization settings.

In Entra, check that all required delegated permissions show as granted.

In the Teams admin center, also check that the built-in apps used for the kit's tabs are available to the installer and intended users.

STEP 6 - Run the customer installation
Build the expected site address from SiteFQDN and MailNickname.

Then run script 02 with ContentMode Customer and SeedDemoContent. Despite its name, SeedDemoContent loads the site's pages, catalogs, calendar, and governance content.

Before allowing the installer to create resources, check the signed-in account, tenant, alias, owner, and target site address shown in the output.

This is a new installation, so don't use ResumeExisting. If an earlier attempt already created resources, follow the recovery procedure instead.

STEP 7 - Run the checker and complete the manual review
Run Test-CoEInstall with the organization folder, site address, and the same content mode used for installation.

Resolve every FAIL. Then read each WARN and complete the manual review it identifies.

Check the site using a reader account, follow the support links, review the security configuration, and look for any remaining demo content.

Save the results. Passing the automated checks is only part of acceptance.

STEP 8 - Publish the reviewed update and test again
Run script 03 with Scope All to publish the reviewed changes.

For the repair demonstrated here, also include RepairCapturedPages. This option can replace managed parts of Home and the captured pages, including some changes made directly in SharePoint. Review what it will replace before using it on an existing site.

After the update, run Test-CoEInstall again and repeat the relevant manual checks.

Complete the handoff only when the checks pass and the required manual reviews are documented.

OUTRO
That completes the eight-step walkthrough.

We've verified the package, checked the tenant and account, installed the site, reviewed the result, and tested a content update.

Keep the organization settings, deployment reports, logs, and review records together. For recovery or removal, follow the administrator guide included with the same release.
