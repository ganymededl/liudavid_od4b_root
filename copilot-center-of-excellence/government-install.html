INTRO
This video walks through a full install of the Copilot Center of Excellence kit in a GCC Moderate tenant. It is the same eight-step process used in production deployments.

You will verify the package, configure the tenant, install the site, and then confirm that it is ready for users - not just that the scripts finished.

STEP 1 - Verify and extract the release package
Start with the release ZIP and the SHA256 receipt downloaded alongside it. Run Get-FileHash with the SHA256 algorithm, and continue only when the calculated value matches the receipt.

Extract the package into a new, empty install folder. Then create a separate organization folder outside the kit.

Keep the deployment settings and records there so replacing the kit will not overwrite them.

STEP 2 - Edit the organization settings
Open Deployment-Settings.json in the organization folder, not the template inside the kit.

Here, you are confirming the tenant name, SharePoint hosts, site alias, visibility, and security settings. For government content, set LearningEnvironment to Government.

If you do not already have an approved provisioning app ID for this tenant, leave PnPClientID blank. Script 01 will fill it in after registration.

STEP 3 - Configure support links and reviewed content
Next, add the organization's approved support and incident-reporting links, along with its governance links, training resources, and custom content.

As each field appears on screen, confirm that it points to a route the responsible team owns and monitors.

Before publishing, have those teams review the governance drafts, support routes, and organization-specific wording.

STEP 4 - Check the content before signing in
From the kit folder, run the two preflight commands shown on screen.

The first loads Internal\ContentPreflight.ps1. The second checks the organization content, including the calendar format and required fields.

Fix any reported issues before connecting to the tenant.

STEP 5 - Install PnP.PowerShell and register the app
Install PnP.PowerShell version 3.2.0.

If PnPClientID is blank because this tenant does not have an approved provisioning app, have someone who can grant tenant-wide admin consent run script 01.

After registration, check that PnPClientID in the organization settings contains the app's client ID.

Here in Entra, confirm that every required delegated permission shows as granted.

Then open the Teams admin center. Confirm that Website, PDF, PowerPoint, and SharePoint pages and lists are available to the installer and intended users.

STEP 6 - Run the customer installation
Before you run anything, work out where the site should land. Combine SiteFQDN and MailNickname from the settings file. The resolved address format is shown on screen.

Now run script 02 in customer mode with SeedDemoContent. That switch loads the site's pages, catalogs, calendar, and governance content.

In the installer output, confirm the signed-in account, tenant, alias, owner, and target site address before resources are created.

For a clean installation, do not use ResumeExisting. If an earlier attempt already created resources, stop and use the Failure and recovery boundary in the administrator guide.

STEP 7 - Run the checker and complete the manual review
Now run Test-CoEInstall with the organization folder, site address, and the same content mode used for installation.

Resolve every FAIL. Then read each WARN and complete the manual review it identifies.

Use a reader account to review the site, follow the support links, confirm the security configuration, and look for remaining demo content.

Save the checker output in the organization folder. Passing the automated checks does not replace the manual review.

STEP 8 - Publish the reviewed update and test again
To publish reviewed content changes, run script 03 with Scope All. Then run Test-CoEInstall again and repeat the relevant manual checks.

RepairCapturedPages is not part of a routine update. Use it only when recovery work or checker results show that preserved managed pages need repair.

The option can replace managed parts of Home and the captured pages, including changes made directly in SharePoint. Review what it will replace before using it on an existing site.

Complete the handoff only when the checks pass and the required manual reviews are documented.

OUTRO
Before handoff, remember that a clean checker run means the build matches the settings. It does not replace content, security, accessibility, or operational review.

Keep the organization settings, deployment reports, logs, checker output, and review records together.

For recovery or removal, use the administrator guide included with the same release.

01Verify and extract the implementation package

Use the frozen implementation ZIP and its matching release receipt. Release 3.8.21 SHA256:

B31F641642BD2199C36C3F840F5A4878CEE8332E89B5C3AB4EC09FF72B264D6F

GitHub ZIP distinction: download the named Copilot-CoE-Implementation-Kit.zip release asset and verify it against the attached .sha256 receipt. GitHub's automatic Source code (zip), Source code (tar.gz), and repository Download ZIP are source snapshots, not installation packages.
$zip = 'C:\path\to\Copilot-CoE-Implementation-Kit.zip'
$expectedHash = 'B31F641642BD2199C36C3F840F5A4878CEE8332E89B5C3AB4EC09FF72B264D6F'
$installRoot = 'C:\CoE-Install\GovernmentOrg'
$kitRoot = Join-Path $installRoot '03_Build\CopilotCoE-Kit'
$orgPath = 'C:\CoE-Orgs\GovernmentOrg'

if ((Get-FileHash -LiteralPath $zip -Algorithm SHA256).Hash -ne $expectedHash) {
  throw 'The chosen release ZIP does not match its receipt.'
}
if (Test-Path -LiteralPath $installRoot) {
  throw "Use a new, empty install folder: $installRoot"
}
if (Test-Path -LiteralPath $orgPath) {
  throw "Use a new organization folder: $orgPath"
}

Expand-Archive -LiteralPath $zip -DestinationPath $installRoot
Copy-Item (Join-Path $kitRoot 'ContentPacks\Government-StateLocal') $orgPath -Recurse
Get-Content (Join-Path $installRoot 'VERSION.txt')

Keep the organization folder outside the extracted kit. Future kit extraction must not overwrite settings, content, assets, transcripts, or deployment identity records.

04Run local preflight before authentication

Set-Location $kitRoot
. .\Internal\ContentPreflight.ps1
Assert-CoEStructuredOrganizationContent -OrgPath $orgPath

This checks organization content locally. It does not validate tenant identity, permissions, URLs, support monitoring, policy approval, or reader experience.

05Install PnP.PowerShell and register the tenant app

Set-Location $kitRoot
$PSVersionTable.PSVersion
Install-Module PnP.PowerShell -RequiredVersion 3.2.0 -Scope CurrentUser
.\01_Register-CoEProvisioningApp.ps1 -OrgPath $orgPath -Interactive

# Confirm script 01 saved a non-empty client ID.
(Get-Content (Join-Path $orgPath 'Deployment-Settings.json') -Raw | ConvertFrom-Json).PnPClientID

Run script 01 once per tenant as an approved consent approver. It creates the single-tenant Copilot CoE Provisioning (PnP) app and saves its client ID in the organization settings file. Never copy that ID to another tenant.

In Microsoft Entra, grant tenant-wide admin consent and confirm these delegated permissions show Granted:

  • Microsoft Graph: Group.ReadWrite.All, ChannelMember.ReadWrite.All, User.Read, and User.Read.All
  • SharePoint: AllSites.FullControl

Before installation, confirm in Teams admin center that the installer and intended CoE users can use these built-in tab providers:

  • Website: com.microsoft.teamspace.tab.web
  • PDF: com.microsoft.teamspace.tab.file.staticviewer.pdf
  • PowerPoint: com.microsoft.teamspace.tab.file.staticviewer.powerpoint
  • SharePoint pages/lists: 2a527703-1f6f-4559-a332-d8a7d288cd88

Use Teams apps > Manage apps. Under app-centric management, App status: Unblocked is not sufficient when Available to says No one; that still denies every user. Select the Microsoft app row and choose Edit availability (or Users and groups > Availability) for the approved users/groups. Do not use Add to team as a substitute. Under legacy app permission policies, verify the policy assigned to the installer and intended users. Policy changes can take hours and up to 24 hours.

06Derive the target and run the clean Customer install

Set-Location $kitRoot
$settings = Get-Content (Join-Path $orgPath 'Deployment-Settings.json') -Raw | ConvertFrom-Json
if ([string]::IsNullOrWhiteSpace($settings.PnPClientID)) {
  throw 'Run script 01 and grant admin consent before installation.'
}
$siteUrl = "https://$($settings.SiteFQDN)/sites/$($settings.MailNickname)"
$contentMode = 'Customer'

& .\02_Install-CopilotCoE.ps1 `
  -OrgPath $orgPath `
  -ContentMode $contentMode `
  -SeedDemoContent

if (-not $?) {
  throw 'Installer did not complete. Stop here; do not read the report, start clean, or purge.'
}

MailNickname chooses the Team alias and SharePoint site path. $siteUrl is derived for validation; changing that variable alone does not change the install target.

-SeedDemoContent is still required in Customer mode because it publishes the managed pages, catalogs, calendar, and governance content. Customer mode filters generated demonstration notices and sample rows.

Before creation, read the signed-in account, tenant, group-naming-policy warning, alias, owner, and target URL printed by the script. Stop if any value is wrong.
Expected optional naming-policy warning: The group naming policy could not be read (Insufficient privileges...). The delegated CoE app intentionally does not request broad Directory.Read.All, so this optional groupSettings read can fail even when the signed-in person is Global Administrator. The warning is non-blocking and does not mean the administrator lacks the roles needed for installation. Do not grant Directory.Read.All solely to remove it. It also does not prove that no naming policy exists: confirm Entra admin center > Groups > Naming policy manually. If the run creates and finds the exact configured alias and proceeds to template application, the alias was not rewritten for that run.

07Run the checker and complete manual acceptance

.\Test-CoEInstall.ps1 `
  -OrgPath $orgPath `
  -SiteUrl $siteUrl `
  -ContentMode $contentMode

Fix every FAIL. Read every WARN and retain evidence for each manual check. At minimum:

  1. Confirm the Home page, navigation, tools, learning paths, support, governance, and catalog views.
  2. Confirm exactly one welcome post in General, Share Your Prompt, and Ask Us Anything.
  3. Confirm no demo notice or sample row remains in Customer mode.
  4. Confirm Team visibility is Private and all three SharePoint sites have external sharing disabled.
  5. Confirm support, technology-request, AI-guidance, and incident links reach approved destinations.
  6. Review as a regular reader, not only as an owner.
  7. Obtain required security, privacy, records, accessibility, licensing, legal, and operational approval.
The provisioning app can send welcome posts but normally cannot read them back without ChannelMessage.Read.All. A checker WARN for that permission is resolved by visual review; do not add the permission solely to eliminate the WARN.

08Publish the reviewed update and check again

For this fresh acceptance run, use the same repair/update sequence documented by the implementation guide. -RepairCapturedPages rewrites managed captured-page elements; review direct SharePoint edits before using it on an established site.

.\03_Update-CoEContent.ps1 `
  -OrgPath $orgPath `
  -Scope All `
  -RepairCapturedPages `
  -AuthenticationMode Interactive `
  -ContentMode $contentMode

.\Test-CoEInstall.ps1 `
  -OrgPath $orgPath `
  -SiteUrl $siteUrl `
  -ContentMode $contentMode
Complete only after both checker runs and manual review. Keep Deployment-Settings.json, CoE-Revision-Report.json, all RevisionAudit transcripts, checker output, and manual acceptance evidence together.

Failure and recovery boundary

  • If the intended Team/site exists after an interrupted run, investigate and resume that exact deployment with -ResumeExisting.
  • Do not start a second clean install against the same alias.
  • Do not delete only the SharePoint site; the Team and Microsoft 365 group remain.
  • Use 04_Remove-CopilotCoE.ps1 -Purge -WhatIf before any reviewed permanent removal.
  • Keep the provisioning app until removal reports AliasReusable : True.
If Teams reports “App is blocked by app permission policy” for com.microsoft.teamspace.tab.web: a Website row showing Unblocked but Available to: No one is still denied. Select the Microsoft Website row, use Edit availability, and choose Everyone or an approved group containing the installer and intended CoE audience. Do not use Add to team. Wait for policy propagation, then resume the existing deployment. Do not start clean or purge. Inspect General, Share Your Prompt, and Ask Us Anything first; pass only confirmed missing welcome posts:
$missingWelcomeChannels = @('General', 'Share Your Prompt', 'Ask Us Anything 📢')
.\02_Install-CopilotCoE.ps1 `
  -OrgPath $orgPath `
  -ContentMode $contentMode `
  -SeedDemoContent `
  -ResumeExisting `
  -PublishWelcomeToChannels $missingWelcomeChannels `
  -AuthenticationMode Interactive `
  -ForceAuthentication

CoE-Revision-Report.json is written only after installation completes. Its absence after a partial failure is expected; do not continue to report-reading or checker commands until resume succeeds.
