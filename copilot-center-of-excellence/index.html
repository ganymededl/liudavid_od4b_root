03Verify and extract the release package

$zip = 'C:\path\to\Copilot-CoE-Implementation-Kit.zip'
$expectedHash = '<SHA256 from the release receipt>'
$installRoot = 'C:\CoE-Install\DemoOrg'
$kitRoot = Join-Path $installRoot '03_Build\CopilotCoE-Kit'
$orgPath = 'C:\CoE-Orgs\DemoOrg'
$profileSource = Join-Path $kitRoot 'Org-Template' # Higher education
# State/local government: $profileSource = Join-Path $kitRoot 'ContentPacks\Government-StateLocal'

if ((Get-FileHash -LiteralPath $zip -Algorithm SHA256).Hash -ne $expectedHash) {
  throw 'The chosen release ZIP does not match its receipt.'
}
Expand-Archive -LiteralPath $zip -DestinationPath $installRoot
Copy-Item $profileSource $orgPath -Recurse

The release receipt supplied with the package records the expected SHA256 for that ZIP. Verify the hash before extracting, and use a new, empty install folder for each clean run.

The separate organization folder holds settings, content overrides, and approved assets outside the install folder, so extracting a newer release does not overwrite them.

Which GitHub ZIP can I install?

Use a prebuilt release asset only when the GitHub release explicitly lists a file named Copilot-CoE-Implementation-Kit.zip and its published receipt or release notes give the SHA256 you verify above. If that asset is present and the hash matches, it is valid installation media.

Do not substitute GitHub's generated source archives: Source code (zip), Source code (tar.gz), or the repository's Code > Download ZIP. Those files are source snapshots, not the frozen implementation package.

Release 3.8.21 currently has no binary assets on GitHub. Obtain the reviewed implementation ZIP and matching receipt through the approved distribution channel. The warning is about source archives, not about a genuine, hash-matched implementation ZIP downloaded from a future GitHub release asset.

This recording uses PowerShell 7.6.7. The kit requires PowerShell 7.4 or later and PnP.PowerShell 3.2.0.

Someone authorized to grant the required app permissions runs the registration script once per tenant, then confirms in Entra that every required delegated permission shows Granted. The script saves the new client ID to the organization settings file.

07Start the clean installation

Set-Location $kitRoot
.\02_Install-CopilotCoE.ps1 `
  -OrgPath $orgPath `
  -ContentMode $contentMode `
  -SeedDemoContent

-SeedDemoContent publishes the pages, catalogs, calendar, and governance content. Without it, the installer creates only the Team and an empty SharePoint site.

The command above uses the $contentMode selected in step 04. Set it to Customer for an approved customer deployment. This recorded lab used Demo to retain demonstration notices. Review source files and existing site content yourself; changing the mode does not replace that review.

This is a clean install, so -ResumeExisting is not used. If an earlier attempt already created a Team or site, investigate first. Then either resume that exact deployment or use 04_Remove-CopilotCoE.ps1 before starting again. Deleting only the SharePoint site leaves the Team and Microsoft 365 group behind, so the next installation can conflict with them.

11Run the read-only checker

.\Test-CoEInstall.ps1 `
  -OrgPath $orgPath `
  -SiteUrl $siteUrl `
  -ContentMode $contentMode

Expected: ALL CHECKS PASSED (...), with every WARN reviewed manually.

The checker does not change the site. Passing it is only part of the review: read every WARN message and complete the manual checks it identifies.

12Review SharePoint as an administrator

Before opening the production site to users, repeat this review with an account that has reader access, not owner access. That reader-account review was not performed in this recording. Also replace every lab-specific value with one the organization has approved.

13Check the welcome messages manually

The provisioning app can send these posts but normally can't read them back, so check them visually. Confirm that each channel has exactly one prepared welcome post, follow its links, and check the demonstration notice.

14Publish a reviewed content update

Use the update script to publish reviewed changes without rebuilding the Team.

This recording also includes -RepairCapturedPages because it demonstrates the repair process on a fresh validation site. This switch rewrites the pages the kit manages. Edits you made to those pages in SharePoint may be lost. Before using it on an existing site, review section D, “Home and the four captured pages,” in 01_Admin-Quickstart.html. That section lists the page elements the switch resets. The update script does not provide a -WhatIf preview.

.\03_Update-CoEContent.ps1 `
  -OrgPath $orgPath `
  -Scope All `
  -RepairCapturedPages `
  -AuthenticationMode Interactive `
        -ContentMode $contentMode

In this recorded run, the update preserved existing catalog rows and checked the security configuration again. Review the output for your own deployment rather than assuming every update will have the same result.

Addendum: sharing a CoE site with an external guest

A publicly accessible guide does not make the deployed SharePoint site public. The kit keeps the Team private and external site sharing disabled by default. Customer installations should retain those defaults; an approved lab preview for a named guest is a separate decision.
