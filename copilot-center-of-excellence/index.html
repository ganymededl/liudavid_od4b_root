07Start the clean installation

Set-Location $kitRoot
$settings = Get-Content (Join-Path $orgPath 'Deployment-Settings.json') -Raw | ConvertFrom-Json
if ([string]::IsNullOrWhiteSpace($settings.PnPClientID)) {
  throw 'Run script 01 and confirm admin consent before installation.'
}
try {
  & .\02_Install-CopilotCoE.ps1 `
    -OrgPath $orgPath `
    -ContentMode $contentMode `
    -SeedDemoContent
} catch {
  throw 'Installation stopped. Inspect the saved transcript and existing Team/site; do not start clean or purge.'
}
if (-not $?) { throw 'Installer did not complete; stop before reading the deployment report.' }
# Read the actual site path after completion; it may be under /teams/ rather than /sites/.
$siteUrl = (Get-Content (Join-Path $orgPath 'CoE-Revision-Report.json') -Raw | ConvertFrom-Json).Site

-SeedDemoContent publishes the pages, catalogs, calendar, and governance content. Without it, the installer creates only the Team and an empty SharePoint site.

The command above uses the $contentMode selected in step 04. Set it to Customer for an approved customer deployment. This recorded lab used Demo to retain demonstration notices. Review source files and existing site content yourself; changing the mode does not replace that review.

This is a clean install, so -ResumeExisting is not used. If an earlier attempt already created a Team or site, investigate first. Then either resume that exact deployment or use 04_Remove-CopilotCoE.ps1 before starting again. Deleting only the SharePoint site leaves the Team and Microsoft 365 group behind, so the next installation can conflict with them.

Script 02 prompts STOP or PROCEED for a long title, lab support mailbox, missing support routes, naming policy, a different owner/operator, or a fallback header. STOP is the default. PROCEED acknowledges that one fact for a reviewed pilot; it does not verify a mailbox, make an incident route work, or waive manual acceptance. Prompts that arise after the Team/site exists require investigation and -ResumeExisting, not another clean run.

The delegated CoE app intentionally omits broad Directory.Read.All, so its optional group-naming-policy read can return Insufficient privileges even for a Global Administrator. Failure and recovery boundary

The eight-phase workflow is the same for HigherEducation and Government content. Do not mistake an interrupted install for a blank tenant: inspect the run transcript and intended Team/site before retrying.

  • If the intended Team/site already exists, correct the blocker and resume that same deployment with -ResumeExisting; never run a second clean install against the same alias.
  • Do not delete only the SharePoint site; the Team and Microsoft 365 group remain.
  • If a Teams tab says App is blocked, verify both App status and Available to. Repair the approved policy, allow it to propagate, and resume; only republish welcome posts whose channels are visually confirmed empty.
  • For a separately approved permanent removal, preview 04_Remove-CopilotCoE.ps1 -Purge -WhatIf first. Keep the provisioning app until removal reports AliasReusable : True.
