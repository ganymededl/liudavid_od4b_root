Administrator deployment guide

Azure AI assessment deployment runbook

Model Mission Control recommends a model from a platform catalog for a given prompt. This runbook deploys the backend for its optional Assess with Azure AI feature.

Users sign in through Microsoft Entra ID. The API validates their access tokens and checks whether they are allowed to use the service. The Function then calls the deployed model in an Azure OpenAI resource using its managed identity.

Cloud scope: this runbook targets an Azure commercial subscription and Microsoft Entra workforce tenant. It has not been validated for Azure Government, GCC High, DoD, or GCC Moderate data-handling requirements; commands, endpoint suffixes, and model availability can differ.
Security model: no Azure OpenAI API key or application client secret is stored in the website or Function App. The HTTP trigger uses Anonymous authorization at the Functions host layer. This does not mean the API accepts unauthenticated requests: the function code validates the token's tenant, audience, delegated scope, and authorized user object ID before calling the Azure OpenAI resource.
Product names: Assess with Azure AI is the feature label in Model Mission Control. The backend resource and API used by this runbook are Azure OpenAI, managed in Microsoft Foundry. Existing foundry_* error codes are application contracts, not separate Azure resources.
Function source package: includes host.json, package manifests, locked dependencies, Function source, authorization and routing libraries, tests, and the source runbook. It excludes node_modules, local settings, credentials, and deployment artifacts.

1. Prerequisites and variables

Prepare the workstation, clone the source, set the target names and origins, and confirm the selected model and quota before creating resources.

Prepare an administrator workstation

  • Contributor on the subscription, or on a pre-created resource group if you skip az group create.
  • User Access Administrator or Owner to assign the Azure OpenAI inference role.
  • Permission to create Entra app registrations and grant delegated consent.
  • Azure CLI, Node.js 22, npm, and Azure Functions Core Tools 4.
  • Git, with permission to clone the Model Mission Control source repository.
  • A globally unique suffix for public Azure resource names.
  • A GitHub Pages or other HTTPS origin for the static frontend.
git clone <source-repository-URL>
cd <source-repository-directory>

The repository root must contain model-mission-control-api/. Section 9 starts from that repository root before changing into the API folder.

$SUFFIX = "<unique-suffix>"
$LOCATION = "eastus2"
$RG = "rg-model-mission-control-$LOCATION"
$STORAGE = "stmmc$SUFFIX"
$FUNCTION_APP = "func-model-mission-control-$SUFFIX"
$AI_ACCOUNT = "mmc-openai-$SUFFIX"
$AI_DEPLOYMENT = "mmc-gpt-5-mini"
$WEB_ORIGIN = "https://<github-user>.github.io"
$WEB_REDIRECT = "$WEB_ORIGIN/<repository>/model-mission-control/"
$LOCAL_ORIGIN = "http://localhost:8765"
$LOCAL_REDIRECT = "$LOCAL_ORIGIN/model-mission-control/"

Use your own tenant, subscription, object IDs, names, and origins. Do not copy IDs from the reference deployment.

Confirm model availability and quota

The first query must return gpt-5-mini version 2025-08-07 with a GlobalStandard SKU. The second must show at least 10 units available in the selected subscription and region.

$Models = @(az cognitiveservices model list `
  --location $LOCATION `
  --query "[?model.name=='gpt-5-mini' && model.version=='2025-08-07' && contains(model.skus[].name, 'GlobalStandard')]" `
  -o json | ConvertFrom-Json)
if ($Models.Count -eq 0) {
  throw "gpt-5-mini 2025-08-07 with GlobalStandard is not offered in $LOCATION."
}

$Quota = az cognitiveservices usage list `
  --location $LOCATION `
  --query "[?name.value=='OpenAI.GlobalStandard.gpt-5-mini'] | [0]" `
  -o json | ConvertFrom-Json
if (-not $Quota) {
  throw "No GlobalStandard quota record was returned for gpt-5-mini in $LOCATION."
}

$AvailableCapacity = [double]$Quota.limit - [double]$Quota.currentValue
if ($AvailableCapacity -lt 10) {
  throw "10 capacity units are required; $AvailableCapacity are available."
}

$Models | Select-Object -ExpandProperty model |
  Select-Object name, version, lifecycleStatus
$Quota | Select-Object @{n="Available";e={$AvailableCapacity}}, currentValue, limit, unit

Do not continue unless both checks pass. The Function App can deploy even when the requested model or capacity is unavailable.

2. Architecture

The browser obtains a delegated access token for the protected API. The Function API validates that token and uses a separate managed-identity token to call Azure OpenAI.

Static websiteMicrosoft Authentication Library (MSAL) redirect sign-in and a defined catalog of eligible models.
Entra IDSingle-tenant single-page application (SPA) token with access_as_user.
Function APIValidates origin, tenant, audience, user, and delegated scope.
Azure OpenAIThe Function App's managed identity invokes the deployed model.

Trust boundaries: browser token to Function; managed identity token from Function to the Azure OpenAI resource. The browser has no Azure OpenAI credential.

Components and responsibilities

ComponentWhat it doesWhy it is needed
Resource groupGroups the backend resources under one cost and lifecycle scope.Use it to filter costs, assign access, and remove resources together.
Static website and HTTPS originServes Model Mission Control, the platform catalogs, MSAL, and ai-config.js.The browser interface is separate from the API. Its exact origin is also used for redirects and CORS.
Model Mission Control Web app registrationRepresents the browser as a public single-page application client.MSAL uses it to sign in the user and request the delegated API scope. It has no client secret.

Storage accountStores Function host state and deployment packages.Azure Functions requires it. The application does not use it to store prompts.
Flex Consumption planAllocates Linux compute when requests arrive.Runs the low-volume API without a continuously running server.

3. Create the Azure OpenAI resource and deploy the model

Create the backend cost boundary and the model endpoint that the Function App will call. The custom subdomain is required for Microsoft Entra token authentication to Azure OpenAI.

Create the resource group, Azure OpenAI account, and model deployment

az group create --name $RG --location $LOCATION

az cognitiveservices account create `
  --name $AI_ACCOUNT `
  --resource-group $RG `
  --location $LOCATION `
  --kind OpenAI `
  --sku S0 `
  --custom-domain $AI_ACCOUNT

az cognitiveservices account deployment create `
  --resource-group $RG `
  --name $AI_ACCOUNT `
  --deployment-name $AI_DEPLOYMENT `
  --model-format OpenAI `
  --model-name gpt-5-mini `
  --model-version 2025-08-07 `
  --sku-name GlobalStandard `
  --sku-capacity 10
Data processing: data stored at rest remains in the designated Azure geography. With GlobalStandard, prompts and responses can be processed in any Azure region. If policy requires US-only processing, use DataZoneStandard only where gpt-5-mini supports that deployment type and region. Verify current availability before deployment. See Microsoft Foundry deployment types.

4. Register the protected API

Register the Function API as a single-tenant resource, define its token audience, and expose the delegated permission the browser must request.

Create the API registration and delegated scope

  1. Open Microsoft Entra admin center > Identity > Applications > App registrations > New registration.
  2. Name it Model Mission Control API; choose Accounts in this organizational directory only.
  3. Open Expose an API and set the Application ID URI to api://<API-CLIENT-ID>.
  4. Add scope access_as_user. Set both admin and user consent display names and descriptions. Enable the scope.
  5. Open Manifest, set api.requestedAccessTokenVersion to 2, and save. New registrations default to null, which issues v1.0 access tokens that do not match this API's issuer and audience checks.

Copy the API registration's Application (client) ID, then assign it for the remaining commands:

$API_CLIENT_ID = "<API-APPLICATION-CLIENT-ID>"

5. Register the single-page application

Register the static website as a public browser client, add its exact redirect URIs, and authorize it to request access_as_user for the protected API.

Create the web registration, redirects, permission, and preauthorization

  1. Create a second single-tenant app registration named Model Mission Control Web.
  2. Under Authentication, add platform Single-page application.
  3. Add $WEB_REDIRECT and $LOCAL_REDIRECT as SPA redirect URIs. Use the main Mission Control directory URL with a trailing slash.
  4. Under API permissions > Add a permission > My APIs, choose the API registration and delegated permission access_as_user.
  5. Return to the API registration > Expose an API > Authorized client applications. Add the web app client ID and select access_as_user.

Copy the web registration's Application (client) ID for ai-config.js:

$WEB_CLIENT_ID = "<WEB-APPLICATION-CLIENT-ID>"

6. Create the Function App

Create the storage and serverless Linux compute that host the protected API. The storage account supports the Function runtime and deployment; it is not prompt storage.

Create Node.js 22 on Linux Flex Consumption

az storage account create `
  --name $STORAGE `
  --resource-group $RG `
  --location $LOCATION `
  --sku Standard_LRS `
  --min-tls-version TLS1_2 `
  --allow-blob-public-access false

az functionapp create `
  --resource-group $RG `
  --name $FUNCTION_APP `
  --storage-account $STORAGE `
  --flexconsumption-location $LOCATION `
  --runtime node `
  --runtime-version 22

az functionapp update `
  --resource-group $RG `
  --name $FUNCTION_APP `
  --set httpsOnly=true

az functionapp config set `
  --resource-group $RG `
  --name $FUNCTION_APP `
  --min-tls-version 1.2

7. Enable managed identity and grant Azure OpenAI access

Give the Function App keyless model access. The identity proves which Azure resource is calling; the role grants that identity inference access on this Azure OpenAI account.

Assign the system identity and least-privilege role

$PRINCIPAL_ID = az functionapp identity assign `
  --resource-group $RG `
  --name $FUNCTION_APP `
  --query principalId -o tsv

$AI_SCOPE = az cognitiveservices account show `
  --resource-group $RG `
  --name $AI_ACCOUNT `
  --query id -o tsv

az role assignment create `
  --assignee-object-id $PRINCIPAL_ID `
  --assignee-principal-type ServicePrincipal `
  --role "Cognitive Services OpenAI User" `
  --scope $AI_SCOPE

8. Configure the Function App

Set the environment-specific identity, authorization, origin, and Azure OpenAI values used by the same Function source package.

Add six application settings

SettingValuePurpose
ENTRA_TENANT_IDYour tenant GUIDRestricts issuer and tenant.
ENTRA_API_CLIENT_IDAPI app client IDValid token audience.
ALLOWED_USER_OBJECT_IDAuthorized user's object IDRestricts the endpoint to the user authorized to run assessments.
ALLOWED_ORIGINSComma-separated exact originsApplication-level CORS allow-list.
AZURE_OPENAI_ENDPOINThttps://<account>.openai.azure.com/Azure OpenAI resource endpoint.
AZURE_OPENAI_DEPLOYMENTYour deployment nameModel deployment the Function calls.

ALLOWED_USER_OBJECT_ID accepts one user object ID. Supporting multiple users or a group requires a code change and a corresponding authorization design review.

The Function App also contains platform-managed storage settings such as AzureWebJobsStorage and DEPLOYMENT_STORAGE_CONNECTION_STRING. With the creation command above, these values are storage connection strings and must be treated as secrets. The security model statement at the top of this runbook applies only to Azure OpenAI API keys and application client secrets.

The user lookup below retrieves the object ID of the account currently signed in to Azure CLI. Use that ID only if this account should be authorized to run assessments. Otherwise, replace it with the intended user's object ID before applying the settings.

$TENANT_ID = az account show --query tenantId -o tsv
$USER_OBJECT_ID = az ad signed-in-user show --query id -o tsv
$AI_ENDPOINT = az cognitiveservices account show `
  --resource-group $RG --name $AI_ACCOUNT `
  --query properties.endpoint -o tsv

az functionapp config appsettings set `
  --resource-group $RG `
  --name $FUNCTION_APP `
  --settings `
    "ENTRA_TENANT_ID=$TENANT_ID" `
    "ENTRA_API_CLIENT_ID=$API_CLIENT_ID" `
    "ALLOWED_USER_OBJECT_ID=$USER_OBJECT_ID" `
    "ALLOWED_ORIGINS=$WEB_ORIGIN,$LOCAL_ORIGIN" `
    "AZURE_OPENAI_ENDPOINT=$AI_ENDPOINT" `
    "AZURE_OPENAI_DEPLOYMENT=$AI_DEPLOYMENT"
Do not use a wildcard (*) in the allowed origins. The function code returns CORS headers only when the request Origin exactly matches ALLOWED_ORIGINS. Keep the platform CORS list empty or equally restrictive; do not weaken the code-level check.

9. Deploy the Function and connect the website

Restore locked dependencies, run the API tests, publish the Function, and point the static website at the deployed API and Entra registrations.

Validate and publish the Node.js project

cd model-mission-control-api
npm ci
npm test
func azure functionapp publish $FUNCTION_APP --javascript --build remote

$FUNC_HOST = az resource show `
  --resource-group $RG `
  --name $FUNCTION_APP `
  --resource-type Microsoft.Web/sites `
  --query properties.defaultHostName -o tsv

Then update model-mission-control/ai-config.js:

window.MODEL_MISSION_AI = Object.freeze({
  enabled: true,
  tenantId: "<TENANT-ID>",
  clientId: "<WEB-APP-CLIENT-ID>",
  scope: "api://<API-APP-CLIENT-ID>/access_as_user",
  apiUrl: "https://<VALUE-OF-FUNC-HOST>/api/recommend",
  redirectUri: window.location.hostname === "localhost"
    ? "http://localhost:8765/model-mission-control/"
    : "https://<github-user>.github.io/<repository>/model-mission-control/"
});
  • Commit the frontend and API source, but never publish local settings, storage connection strings, tokens, or deployment credentials.
  • When authentication settings change, update the version on the ai-config.js script URL so browsers load the revised configuration.
  • The frontend uses full-page MSAL redirect authentication and resumes the assessment from session storage after sign-in.

Remove development access before production approval

  1. In the web app registration, remove http://localhost:8765/model-mission-control/ from the SPA redirect URIs.
  2. Remove the localhost origin from the Function setting:
az functionapp config appsettings set `
  --resource-group $RG `
  --name $FUNCTION_APP `
  --settings "ALLOWED_ORIGINS=$WEB_ORIGIN"

10. Validate end to end

A successful deployment does not prove that token validation, CORS, authorization, managed identity, or catalog restrictions work. Test each boundary in order.

Run the acceptance checks in order

  1. Deployment: Function App state is Running and /api/recommend exists.
  2. Anonymous denial: POST without a bearer token returns HTTP 401.
  3. CORS: OPTIONS from the production origin returns 204 and that exact Access-Control-Allow-Origin.
  4. Authentication: selecting Assess with Azure AI redirects the current tab to Microsoft Entra ID. After sign-in, Model Mission Control restores the selected platform and prompt, then continues the assessment automatically.
  5. Authorization: sign in with a same-tenant test user whose object ID is not configured in ALLOWED_USER_OBJECT_ID. Submit a synthetic assessment and confirm HTTP 403. A user from another tenant should be blocked during Entra sign-in because both registrations are single tenant.
  6. Managed identity: in a dedicated test environment, temporarily remove the managed identity's Azure OpenAI role assignment. Confirm that the response contains foundry_authentication_failed. Restore the assignment, allow time for role propagation, and retest.
  7. Eligible models: verify that the response references only model IDs included in the assessment request from the selected platform's catalog.
# Expected output: 401 in Windows PowerShell 5.1 and PowerShell 7
try {
  Invoke-WebRequest `
    -Uri "https://$FUNC_HOST/api/recommend" `
    -Method Post `
    -ContentType "application/json" `
    -Body '{}' `
    -UseBasicParsing | Out-Null
  throw "Expected HTTP 401 but the request succeeded."
}
catch {
  $status = [int]$_.Exception.Response.StatusCode
  if ($status -ne 401) { throw }
  $status
}

# Expected: HTTP 204 plus exact production origin
Invoke-WebRequest `
  -Uri "https://$FUNC_HOST/api/recommend" `
  -Method Options `
  -Headers @{
    Origin = $WEB_ORIGIN
    "Access-Control-Request-Method" = "POST"
    "Access-Control-Request-Headers" = "authorization,content-type"
  } `
  -UseBasicParsing |
  Select-Object StatusCode, @{n="ACAO";e={$_.Headers["Access-Control-Allow-Origin"]}}

11. Troubleshooting and rollback

Start with the symptom below. Error codes retain the foundry_ prefix for compatibility while the Function calls the Azure OpenAI resource.

SymptomLikely causeAction
AADSTS50011Redirect URI mismatchMatch scheme, host, path, and trailing slash under the SPA platform.
Login succeeds but assessment does not resumeCached frontend or stale MSAL stateVersion the config script, close stale tabs, and clear site session storage.
HTTP 401Missing, expired, wrong-audience, or wrong-issuer tokenCheck tenant, API client ID, scope URI, and MSAL configuration.
HTTP 403Origin, user object ID, or delegated scope rejectedCheck ALLOWED_ORIGINS, ALLOWED_USER_OBJECT_ID, and the token's scp (delegated scopes) claim.
foundry_authentication_failedManaged identity role missing or not propagatedVerify system identity and Cognitive Services OpenAI User at the Azure OpenAI account scope; wait for propagation.
foundry_request_failed with HTTP 404Wrong endpoint or deployment nameUse the Azure OpenAI endpoint and deployment name exactly as shown in Model deployments.
Browser CORS errorOrigin not exact or preflight rejectedDo not include paths in ALLOWED_ORIGINS; include only scheme and host/port.

Disable the feature

  1. Set enabled: false in model-mission-control/ai-config.js.
  2. Increment the version on the ai-config.js script URL in model-mission-control/index.html, then publish the site.
  3. Confirm that Assess with Azure AI is hidden and the local advisor still works.

Block backend access

Follow the approved access-revocation procedure. Depending on the incident, disable the delegated API scope, remove SPA preauthorization, or remove the Function managed identity's Azure OpenAI role assignment. Allow several minutes for an Azure role change to take effect.

Remove resources

Run these commands only after retention and change-control approval. In a new PowerShell session, rerun the Section 1 variable block and set the two app registration client IDs. Deleting the resource group removes the Function App, plan, storage, Application Insights, Azure OpenAI account, and model deployment. Purging the soft-deleted Azure OpenAI account allows its name to be reused.

$API_CLIENT_ID = "<API-APPLICATION-CLIENT-ID>"
$WEB_CLIENT_ID = "<WEB-APPLICATION-CLIENT-ID>"

az group delete --name $RG --yes

az cognitiveservices account purge `
  --location $LOCATION `
  --resource-group $RG `
  --name $AI_ACCOUNT

az ad app delete --id $WEB_CLIENT_ID
az ad app delete --id $API_CLIENT_ID

Do not weaken the trust boundaries to troubleshoot. Never add a browser-visible Azure OpenAI API key, wildcard CORS, a client secret to the static site, or subscription-wide Owner permissions.
