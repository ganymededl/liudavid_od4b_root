What happened

  1. Initial T4 and T5 runs returned the canary values even though Word Online displayed the sensitivity labels.
  2. Activity Explorer contained no P3 matches for those runs.
  3. SharePoint REST inspection showed an empty _IpLabelId field on both files.
  4. Reopening each file and explicitly selecting its label again populated _IpLabelId within about one minute.
  5. Immediate T4 and T5 behavioral retests refused to read the files, named the sensitivity label and Purview DLP policy, and did not reveal the canaries.
  6. T8c-1 returned the Research-Plan content for the non-Testers control, confirming the policy did not over-apply in that completed control.
  7. T8c-2 remained inconclusive because the Clinical-Summary file could not be located for the control user.
Evidence boundary: these observations point to a label-metadata synchronization failure rather than a rule-configuration problem. The exact underlying synchronization mechanism was not independently confirmed.
