Prompt Escape Room quickstart

Use this guide to recreate the same HE/SLG Prompt Escape Room in your own tenant, with secure sign-in and Azure AI Foundry scoring.

Security model: the browser holds no Foundry API key. Users sign in, call your protected Function API, and the Function uses managed identity to call Foundry.

Prerequisites (do this first)

  • Azure subscription access (Contributor or Owner) for the target resource group.
  • Permission to create App registrations in Microsoft Entra ID.
  • GitHub repo where you can publish static files through GitHub Pages (or equivalent HTTPS static host).
  • Azure CLI installed and signed in on your workstation.
  • Node.js 22+ and npm installed (for tests/build validation).
  • Your user object ID (for ALLOWED_USER_OBJECT_ID) if you want to restrict scoring to specific users.

If you need broad access, replace single-user gating with your own group-based authorization logic before production rollout.

Step-by-step setup

1. Publish the frontend pages

Publish these folders to your GitHub Pages repository:

  • prompt-engineering-public/
  • prompt-escape-room/
  • model-mission-control/vendor/msal-browser.min.js (already referenced by the page)

Checkpoint: open the public Prompt Engineering page and confirm the Escape Room card appears.

2. Create the API app registration (click-by-click)

  1. Go to portal.azure.com → Microsoft Entra ID.
  2. Open App registrations → New registration.
  3. Name it (example: prompt-escape-room-api).
  4. Choose Accounts in this organizational directory only.
  5. Click Register.
  6. Open Expose an API → set an Application ID URI (format: api://<api-client-id>).
  7. Click Add a scope and create access_as_user.

Copy the Application (client) ID and new scope URI. You will need both later.

3. Create the SPA app registration (click-by-click)

  1. In App registrations, click New registration.
  2. Name it (example: prompt-escape-room-spa).
  3. Choose single-tenant account type.
  4. Register the app, then open Authentication.
  5. Click Add a platform → Single-page application.
  6. Add both redirect URIs:
https://<your-gh-user>.github.io/<your-repo>/prompt-escape-room/
http://localhost:8765/prompt-escape-room/
  1. Open API permissions → Add a permission → My APIs → choose your API app.
  2. Select delegated scope access_as_user, then grant admin consent.

5. Configure Function app settings

In your Function App, open Settings > Environment variables and add:

ENTRA_TENANT_ID=<your-tenant-guid>
ENTRA_API_CLIENT_ID=<api-app-client-id-guid>
ALLOWED_USER_OBJECT_ID=<allowed-user-object-id-guid>
ALLOWED_ORIGINS=https://<your-gh-user>.github.io
ESCAPE_AOAI_ENDPOINT=https://<your-aoai-account>.openai.azure.com/
ESCAPE_AOAI_DEPLOYMENT=<your-deployment-name>

Save and restart the Function App.

Azure portal > Function App > Environment variables
Setting name
ENTRA_TENANT_ID ... ESCAPE_AOAI_DEPLOYMENT
Red callout: ALLOWED_ORIGINS must include your exact site origin.

6. Grant managed identity access

  1. Open Function App → Identity → turn on System assigned.
  2. Open your Azure OpenAI resource → Access control (IAM).
  3. Click Add role assignment and choose role Cognitive Services OpenAI User.
  4. Assign access to Managed identity, then select your Function App identity.

8. Validate end-to-end

  • Open Prompt Escape Room from your public hub page.
  • Switch scoring engine to Live AI score (Foundry).
  • Sign in with your tenant account.
  • Submit a prompt and confirm score + feedback return successfully.

Reference sign-in pattern

The DIAx sign-in pattern used here mirrors Model Mission Control's browser sign-in + token-based API call flow.

Troubleshooting quick hits

  • AADSTS50011 redirect mismatch: add the exact deployed redirect URI to the SPA app registration.
  • WAM 700003 device deleted: use browser-based sign-in (InPrivate) and re-register/sign-in the work account on the device.
  • Foundry selected but still disabled: confirm sign-in succeeded and API scope consent was granted.
  • 403 origin_not_allowed: include your page origin in ALLOWED_ORIGINS.
  • 502 foundry_request_failed: verify AOAI deployment name and managed identity role assignment.
