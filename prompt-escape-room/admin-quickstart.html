Prompt Quest quickstart

This is a full build guide: source, infrastructure, app registration, API deployment, room configuration, and release checks.

What this deploys: static web app + protected Function API + managed identity call to Azure OpenAI model deployment. No browser API keys.
Naming note: this app reuses backend patterns and vendor assets from Model Mission Control, so you will see source folders named model-mission-control/ and model-mission-control-api/ in this Prompt Quest deployment.

Prerequisites and access

  • Azure subscription access for target resource group.
  • Permission to create App registrations in Microsoft Entra ID.
  • Permission to create role assignments (Microsoft.Authorization/roleAssignments/write) for IAM step.
  • GitHub repository where you can publish static files via GitHub Pages (or equivalent HTTPS host).
  • Azure CLI + Node.js 22 + npm on workstation.
  • A tenant admin or delegated admin available to grant API permissions consent.

Terms used in this guide: AOAI = Azure OpenAI resource. Foundry scoring here means the app calling your AOAI model deployment through the Function API.

Step-by-step build

1. Get source and prepare static publish

  1. Clone your repository locally (or copy these folders into your existing site repo).
  2. Confirm these paths are present:
    • prompt-engineering-public/
    • prompt-escape-room/
    • model-mission-control-api/
    • model-mission-control/vendor/msal-browser.min.js
  3. Publish your repo to GitHub Pages.
git clone https://github.com/<your-user>/<your-repo>.git
cd <your-repo>
git push origin main

If your Pages source is branch/folder based, configure that in repository settings before testing URLs.

2. Create API app registration (Entra)

  1. Portal → Microsoft Entra ID → App registrations → New registration.
  2. Name it prompt-escape-room-api (or your naming standard).
  3. Use single tenant.
  4. Register, then open Expose an API.
  5. Set Application ID URI to api://<api-client-id>.
  6. Add scope:
    • Name: access_as_user
    • Who can consent: Admins and users
    • Display text: allow frontend to call scoring API

3. Create SPA app registration (Entra)

  1. Create another app registration: prompt-escape-room-spa.
  2. Open Authentication → Add a platform → Single-page application.
  3. Add redirect URIs exactly:
https://<your-gh-user>.github.io/<your-repo>/prompt-escape-room/
http://localhost:8765/prompt-escape-room/
  1. Open API permissions → Add a permission → My APIs → choose API app.
  2. Select delegated access_as_user.
  3. Grant admin consent.

4. Create Azure infrastructure (including Function App)

# Replace with your values
$RG = "rg-prompt-escape-room-eastus2"
$LOCATION = "eastus2"
$STORAGE = "stpromptroom12345"
$PLAN = "plan-prompt-room"
$FUNC = "func-prompt-room-12345"
$AOAI = "aoai-prompt-room-12345"
$DEPLOYMENT = "prompt-score-gpt41mini"

az group create --name $RG --location $LOCATION

az storage account create `
  --name $STORAGE `
  --resource-group $RG `
  --location $LOCATION `
  --sku Standard_LRS

az functionapp plan create `
  --name $PLAN `
  --resource-group $RG `
  --location $LOCATION `
  --sku B1 `
  --is-linux

az functionapp create `
  --name $FUNC `
  --resource-group $RG `
  --plan $PLAN `
  --storage-account $STORAGE `
  --runtime node `
  --runtime-version 22

az cognitiveservices account create `
  --name $AOAI `
  --resource-group $RG `
  --location $LOCATION `
  --kind OpenAI `
  --sku S0 `
  --custom-domain $AOAI

If your standards require Consumption plan on Windows, use this variant:

az storage account create --name $STORAGE --resource-group $RG --location $LOCATION --sku Standard_LRS
az functionapp create --name $FUNC --resource-group $RG --storage-account $STORAGE --consumption-plan-location $LOCATION --os-type Windows --runtime node --runtime-version 20

If your organization uses a different hosting SKU or region policy, adjust accordingly.

5. Deploy model in Azure OpenAI

az cognitiveservices account deployment create `
  --resource-group $RG `
  --name $AOAI `
  --deployment-name $DEPLOYMENT `
  --model-format OpenAI `
  --model-name gpt-4.1-mini `
  --model-version 2024-07-18 `
  --sku-name GlobalStandard `
  --sku-capacity 10

Use your approved model/version if different. Keep deployment name, because you will reuse it in app settings.

7. Configure Function app settings

$TENANT = "<tenant-id>"
$API_CLIENT = "<api-app-client-id>"
$ALLOWED_USER = "<user-object-id>"
$ORIGIN = "https://<your-gh-user>.github.io"
$AOAI_ENDPOINT = "https://$AOAI.openai.azure.com/"

az functionapp config appsettings set `
  --resource-group $RG `
  --name $FUNC `
  --settings `
  ENTRA_TENANT_ID=$TENANT `
  ENTRA_API_CLIENT_ID=$API_CLIENT `
  ALLOWED_USER_OBJECT_ID=$ALLOWED_USER `
  ALLOWED_ORIGINS=$ORIGIN `
  ESCAPE_AOAI_ENDPOINT=$AOAI_ENDPOINT `
  ESCAPE_AOAI_DEPLOYMENT=$DEPLOYMENT
# Platform-level CORS (required for browser preflight)
az functionapp cors add `
  --resource-group $RG `
  --name $FUNC `
  --allowed-origins $ORIGIN

Portal path: Function App > API > CORS. Add your GitHub Pages origin. If your security policy requires it, enable Access-Control-Allow-Credentials.

Function App > Environment variables + API > CORS
Critical value
ALLOWED_ORIGINS = exact site origin
Red callout: set both app-level ALLOWED_ORIGINS and platform CORS allow list, or browser requests will fail.

8. Enable managed identity and assign AOAI role

az functionapp identity assign `
  --resource-group $RG `
  --name $FUNC

$PRINCIPAL_ID = az functionapp identity show `
  --resource-group $RG `
  --name $FUNC `
  --query principalId -o tsv

$AOAI_ID = az cognitiveservices account show `
  --resource-group $RG `
  --name $AOAI `
  --query id -o tsv

az role assignment create `
  --assignee-object-id $PRINCIPAL_ID `
  --assignee-principal-type ServicePrincipal `
  --role "Cognitive Services OpenAI User" `
  --scope $AOAI_ID

In prompt-escape-room/index.html, update the DIAx_AI object:

tenantId: "<your-tenant-id>",
clientId: "<your-spa-client-id>",

Commit and push these changes so they publish to your site.

10. Room authoring: edit scenarios, tasks, scoring, certificate

Admins can customize the room itself in prompt-escape-room/index.html:

  • Scenarios and roles: update roleCatalogByMode for HE and SLG.
  • Assignment text and tasks: edit each role's assignmentTitle, assignmentText, and tasks.
  • Local rubric behavior: adjust evaluatePromptLocal() thresholds and feedback.
  • Pass/fail language: labels returned in local and Foundry paths.
  • Certificate text: update completion wording in certificate section.

This is the section that lets admins create their own room, not only copy your existing one.

11. Validate and release

Run this checklist before sharing with users:

  • Public page opens and room loads.
  • Local scoring works and records attempt history.
  • Foundry scoring sign-in works and returns feedback.
  • Unauthorized user is rejected (403 expected).
  • Task progression and reset room controls work.
  • Completion certificate renders and prints.

Reference sign-in pattern

This implementation follows the same DIAx browser sign-in pattern used in Model Mission Control.

Multi-user deployment guidance

Current sample uses ALLOWED_USER_OBJECT_ID for a controlled setup. For workshops or production, replace that gate with one of:

  • Allowed security group IDs from token claims.
  • Allowed app roles.
  • Tenant-wide access with explicit abuse controls and monitoring.

Do not remove authorization checks without replacing them with a supported access model.

Troubleshooting

  • AADSTS50011: redirect URI mismatch. Add exact URI with trailing slash to SPA app registration.
  • WAM 700003: local device account issue. Use browser sign-in (InPrivate) and re-register work account on device.
  • 403 origin_not_allowed: origin not in ALLOWED_ORIGINS.
  • 403 forbidden: token valid but user not authorized by API logic.
  • 502 foundry_request_failed: model deployment name mismatch or missing AOAI role assignment for Function identity.
