Inside a Microsoft 365 Copilot CoE site

A screenshot-led, plain-language tour for IT admins — what each section of a Copilot Center of Excellence (CoE) hub does, and why it's there. Built from the open-source CopilotCoE-Kit.

A Copilot CoE is a single Team + SharePoint site that gives an organization one place to learn Copilot, find vetted prompts and agents, read the real AI rules, and ask for help — instead of scattering that across email threads and one-off Teams posts. The screenshots below are from a real, fully deployed demo build (not mockups), captured right after its install script reported:

01Home — one page, five next steps

Instead of a wall of links, the home page is five tiles: Start in 10 minutes, Learning paths by role, Prompt library by role, Agent Showcase, Get help. A first-time visitor always has an obvious next click. A one-line banner under the tiles plainly states this is a demo build with sample guidance, not official policy.

02Start in 10 minutes — the on-ramp for novices

This is the first click on purpose: most people have never opened Copilot. Four timed steps take someone from "never used it" to "got one good result" — sign in the right way (look for the green shield), know what's safe to paste, try a prompt written for their role, then check the answer before trusting it. No training enrollment required.

03Learning paths by role — training sorted so people skip what doesn't apply

Faculty, staff, students and IT don't need the same training, so steps are grouped by role and each one links to the live session calendar or a ready-made prompt to practice with — not a blank box. This page doesn't track who finished what; that stays in the organization's own learning system.

04Prompt library by role — 230 starting points instead of a blank page

The blank prompt box is one of the biggest adoption blockers. This catalog ships 230 ready-to-adapt prompts by role and task type — copy one, fill in the brackets, done. An organization can add its own CSV files to extend or replace any of these without touching the kit itself.

05Agent Showcase — a reviewed catalog, not a free-for-all

Every listed agent shows its data sources, access requirements and an owner, so people reuse something vetted instead of requesting a brand-new build. New submissions go through native SharePoint content approval before they appear — a reviewer group, not the whole site, sees drafts.

06Get help — turns a question into a specific request

A simple table replaces a generic "contact us" box: get help using Copilot, request a license, book a department workshop, propose a new agent, or report a data/safety concern — each routed differently so nothing gets stuck in one inbox. Data or safety reports are called out separately from ordinary feedback.

07Governance and Responsible AI — the actual rules, in one place

Answers the question people actually ask: "can I paste this into Copilot?" A data-classification table (public / internal / confidential) and a three-tier risk model for agents means most of that question is answerable here, without a committee meeting every time. A sample RACI shows who owns what decision; organizations swap in their real role names.

08Success Stories — peer proof, with guardrails built into the submission steps

A short video from a real colleague beats a vendor pitch. The submission steps bake in the guardrails — no student, health, financial or ID data, consent from everyone shown, captions required — and every story goes through content approval before it's published.

09Feedback and Roadmap — keeps the program from going stale

One page for "what's coming" (Microsoft's own Copilot release notes and roadmap) and "what we're doing about it" (the organization's own milestone plan), plus a channel to ask for what's missing — so every suggestion doesn't need its own new form.

Get the kit

Everything above is produced by one config-driven PowerShell kit: the same scripts build this for any organization by changing an Deployment-Settings.json file in a separate organization folder — nothing organization-specific is edited inside the kit itself.

  • Private by default. The Team is Private and external SharePoint sharing is Disabled unless an admin explicitly turns it on for a reviewed lab preview.
  • Delegated, interactive sign-in only. A tenant-owned Entra app is used for provisioning — no certificates or stored secrets.
  • Re-runnable and reversible. An update script republishes edited content; a removal script tears the whole thing down (soft-delete by default).
  • Self-checking. A test script verifies pages, navigation, catalogs, permissions and links after every install — the 98-check pass above came from that script, not a manual review.
